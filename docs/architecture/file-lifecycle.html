The four ways a file comes back clean

All four print the same word to whoever asked. Three are fine. The fourth is the bug class this codebase keeps rediscovering, and every “a warning means this” rule elsewhere exists to keep that column empty.

What keeps this true

scripts/conformance.sh asks the same five questions of every capability Siphon advertises. The damaged column is the one that earns its keep — it fails when a reader returns Ok("") for a file it could not parse, which is exactly how outcome 4 happens.

json / evasive

The normalizer decodes HTML entities, percent-encoding, base64, base32 and hex — but not JSON \uXXXX escapes. JSON is a first-class input format, so a value spelled that way passes through unread.

mbox / damaged

A malformed From  line yields zero characters with no warning. That is outcome 4, and the one place it is currently reachable.

xlsx / evasive

Whitespace normalization collapses the cell separator, so two adjacent 8-digit cells still read as one Luhn-valid card. Recorded rather than fixed, because the fix is not local: that normalization is what defeats a whole class of evasion.
